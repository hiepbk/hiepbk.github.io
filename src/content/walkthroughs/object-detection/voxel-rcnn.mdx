## Motivation & Main Contribution

- By 2020 the leaderboards were led by point-based or point–voxel detectors (PointRCNN, STD, 3DSSD, **PV-RCNN**),
  and the common belief was: **precise raw-point positions are needed for accurate boxes**.
- Voxel R-CNN tests that belief and rejects it: **coarse voxels are enough**, if the second stage reads the
  **3D** voxel features instead of only the BEV map.
- Design: SECOND-style 3D sparse backbone → 2D BEV backbone + RPN → **voxel RoI pooling** → detect head.
  No keypoints, no raw points in the second stage.
- **Main contributions:**
  1. **Voxel RoI pooling** — RoI-grid features pooled directly from sparse 3D voxel volumes.
  2. **Voxel query** — neighbour search by voxel indices instead of PointNet++ ball query.
  3. **Accelerated PointNet module** — split the first FC layer to cut the cost of local aggregation.
- Result: PV-RCNN-level accuracy on KITTI at **25.2 FPS** vs. 8.9 FPS for PV-RCNN.

## Challenges at the Time

- The paper's own diagnosis compares **SECOND** and **PV-RCNN** on KITTI val (car, moderate, R11):
  - SECOND: **78.62** AP. Adding a BEV detect head (rotated RoI Align on the BEV map): only **79.26** (+0.6).
  - PV-RCNN: **83.69**. So box refinement helps a bit, but **BEV features alone are too limited** — 3D
    structure is what matters (Table 1).
- **Point–voxel interaction is slow.** In PV-RCNN, VSA takes **49.4 ms** of about 99 ms per frame —
  3D backbone 21.1 ms, 2D backbone 9.4 ms, detect head 19.1 ms (Table 2).
- **Ball query on voxels is still expensive**: finding neighbours of a query point among $N$ voxels is $O(N)$.

## Naive Questions

- **If voxels lose precise positions, how can refinement work without raw points?**
  The voxel features already encode local geometry; the experiments show that is almost sufficient.
- **Why not RoI-pool from the BEV map, like a 2D detector?**
  Tried in the paper: +0.6 AP only. The height structure is gone in BEV.
- **Why not max-pool the voxels inside each sub-cell, like Fast R-CNN's RoI pooling?**
  Fewer than 3% of voxels are non-empty; most sub-cells would be empty.
- **What is wrong with ball query?**
  Nothing in accuracy — it is just slow. Voxels sit on a grid, so neighbours can be looked up by index.
- **Why the Manhattan distance?**
  On voxel indices it is cheap to compute and enumerate: add offsets like $(\Delta i, \Delta j, \Delta k) \in \{-1, 0, 1\}^3$.
- **Is this just PV-RCNN without keypoints?**
  Roughly, yes — the RoI-grid idea stays, the keypoint detour goes.

## Key Idea

> **Key idea.** Keep the whole detector in voxels: pool each proposal's grid-point features directly from the
> sparse 3D feature volumes, using index-based voxel queries instead of point-based ball queries.

For grid point $g_i$ with its queried neighbour voxels $\{v_i^1, \dots, v_i^K\}$:

$$
\eta_i = \max_{k = 1, \dots, K} \Big\{ \Psi\big( [\, v_i^k - g_i \,;\, \phi_i^k \,] \big) \Big\}
$$

- $v_i^k - g_i$: relative position of voxel centre $k$; $\phi_i^k$: its feature; $\Psi$: an MLP;
  $\max$: channel-wise max pool — the PointNet recipe once more, now on voxel centres.

> **Builds on.** PointNet's shared MLP + max pool ([walkthrough 01](/walkthroughs/object-detection/pointnet/)).

Voxel query uses the Manhattan distance on voxel indices:

$$
D_m(\alpha, \beta) = |i_\alpha - i_\beta| + |j_\alpha - j_\beta| + |k_\alpha - k_\beta|
$$

### The pipeline, step by step

1. **Voxelize** the scan.
2. **3D backbone**: sparse 3D convolutions, four stages (SECOND / PV-RCNN design).
3. **BEV**: stack the output along Z into a BEV map.
4. **2D backbone + RPN**: two conv blocks, multi-scale fusion, two sibling $1 \times 1$ convs → anchor proposals.
5. **Proposals**: NMS with IoU 0.7, keep top 100.
6. **Voxel RoI pooling**: $6 \times 6 \times 6$ grid per proposal; features from the **last two** 3D stages,
   two query distances per stage.
7. **Detect head**: shared 2-layer MLP → box-residual branch and IoU-guided confidence branch; final NMS with IoU 0.1.

> **Builds on.** SECOND's sparse 3D backbone and BEV RPN ([walkthrough 04](/walkthroughs/object-detection/second/)),
> and PV-RCNN's RoI grid and IoU-guided scoring ([walkthrough 07](/walkthroughs/object-detection/pv-rcnn/)).

- Waymo: range $[-75.2, 75.2]$ m in X and Y, $[-2, 4]$ m in Z; voxel size $(0.1, 0.1, 0.15)$ m; 2D channels
  (128, 256); aggregation output 64 channels.

### Voxel query: neighbours by index

- Treat the sparse volume as a set of non-empty voxel centres $\{v_i\}$ with features $\{\phi_i\}$.
- Quantise the query point to a voxel, then reach its neighbours by **index offsets**; keep up to $K$ voxels within
  a Manhattan-distance threshold.
- Cost: $O(K)$ per query, vs. $O(N)$ for a ball query over $N$ non-empty voxels.

### Voxel RoI pooling

- Divide each proposal into $G \times G \times G$ sub-voxels ($G = 6$); each sub-voxel centre is a grid point.
- Because the volume is so sparse (< 3% non-empty), do not max-pool inside sub-voxels — instead, **gather
  neighbouring voxels** around each grid point with voxel query and aggregate them with the PointNet module above.
- Pool from the last two 3D stages, two distance thresholds each, and **concatenate** the four results as the RoI feature.
- Compared with PV-RCNN: the same idea of grid points inside the box, but they look up **voxels**, not keypoints.

### Accelerated local aggregation

- With $M = r \times G^3$ grid points ($r$ RoIs) and $K$ voxels each, the first FC layer on $[\text{coords}; \text{feature}]$
  costs $O(M \times K \times (C + 3) \times C')$.
- Split its weight $W \in \mathbb{R}^{C' \times (C+3)}$ into $W_F \in \mathbb{R}^{C' \times C}$ (features) and
  $W_C \in \mathbb{R}^{C' \times 3}$ (coordinates):
  - apply $W_F$ **once per voxel**, before the query;
  - after the query, apply only $W_C$ to the relative coordinates and add.
- New cost: $O(N \times C \times C' + M \times K \times 3 \times C')$ — cheaper, since $M \times K$ is an order of
  magnitude larger than $N$.

### Losses

- **RPN** (as SECOND / PointPillars): focal loss for classification, Huber loss for box regression on foreground anchors.
- **Detect head**: IoU-shaped confidence target

$$
l_i^*(\mathrm{IoU}_i) =
\begin{cases}
0 & \mathrm{IoU}_i < \theta_L \\
\dfrac{\mathrm{IoU}_i - \theta_L}{\theta_H - \theta_L} & \theta_L \le \mathrm{IoU}_i < \theta_H \\
1 & \mathrm{IoU}_i > \theta_H
\end{cases}
\qquad \theta_L = 0.25,\; \theta_H = 0.75
$$

- Binary cross-entropy on $l_i^*$; Huber loss for box residuals on proposals with IoU ≥ $\theta_{reg} = 0.55$.
- 128 sampled RoIs per scene, half of them positive. Trained end to end with Adam, lr 0.01, cosine annealing
  (KITTI: 80 epochs, batch 16). Implemented in OpenPCDet.

### Pros and Cons

- **Pros**
  - PV-RCNN-level accuracy from voxels alone, about three times faster (25.2 vs 8.9 FPS).
  - Voxel query uses the grid: neighbours by index, $O(K)$ instead of $O(N)$.
  - Splitting the first FC layer removes most of the per-neighbour compute.
  - Biggest gains far away on Waymo (+10.98 mAP beyond 50 m over PV-RCNN).
- **Cons**
  - Still anchor-based proposals from a BEV RPN.
  - Sparse convolutions keep a local receptive field.
  - LiDAR only: far and small objects stay sparse.

### Future Work

- Wider context than local sparse convolutions — e.g. attention over sparse voxels.
- Fusing camera images to help where LiDAR points are scarce.
