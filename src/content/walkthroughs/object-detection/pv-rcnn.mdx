## Motivation & Main Contribution

- Two families now compete:
  - **Grid-based** (VoxelNet, SECOND, PointPillars): efficient, high-quality proposals, but the receptive
    field is tied to the kernel size and the features are quantised.
  - **Point-based** (PointRCNN): PointNet++ set abstraction keeps exact locations and a flexible receptive
    field (any radius), but is costly on a whole scene.
- PV-RCNN — from the PointRCNN authors — takes the best part of each:
  - a **3D sparse-convolution voxel CNN** (SECOND-style) as backbone and proposal network;
  - **PointNet++ set abstraction** to gather voxel features for second-stage refinement.
- **Main contributions:**
  1. **Voxel-to-keypoint scene encoding** (Voxel Set Abstraction, VSA): summarise the whole scene in a few
     thousand keypoints.
  2. **Keypoint-to-grid RoI feature abstraction** (RoI-grid pooling): pool keypoint features to a grid of
     points inside each proposal, with multiple radii.
- Ranked 1st on the KITTI car 3D leaderboard (as of Nov. 15, 2019) and set a new mark on Waymo.

## Challenges at the Time

- **Pooling from voxel CNN features is poor.** The last feature volume is downsampled up to $8\times$ —
  too coarse for precise boxes. Upsampled volumes are still **sparse**, so trilinear / bilinear RoI pooling
  (8 / 4 neighbours) mostly reads zeros.
- **Set abstraction directly on voxels is too expensive.** A KITTI scene can have ~18,000 voxels in the
  $4\times$-downsampled volume. With 100 proposals × $3 \times 3 \times 3$ grid points, that is
  $2{,}700 \times 18{,}000$ pairwise distances — even a small grid does not fit.
- **Point-based backbones** (PointRCNN) recall fewer good proposals than a voxel CNN with anchors (Table 4).

## Naive Questions

- **Why not just add a second stage to SECOND?**
  RoI pooling on sparse, downsampled feature maps gathers mostly empty cells (see above).
- **Why keypoints, and not all voxels?**
  2,048 keypoints (KITTI) are a small, fixed-size bridge; grid points then search only among them.
- **How are keypoints chosen?**
  Farthest point sampling on the raw points — the same FPS as in PointNet++.
- **Many keypoints land on the road. Does that hurt?**
  A small head predicts a foreground weight per keypoint and down-weights the background ones.
- **Why grid points instead of the points inside the box?**
  A fixed $6 \times 6 \times 6$ grid gives a fixed-size RoI feature, and the radii reach beyond the box for context.
- **Why predict IoU instead of a class score?**
  An IoU-shaped target ranks boxes by localisation quality; it beats a plain classification target (Table 9).

## Key Idea

> **Key idea.** Encode the scene with a sparse voxel CNN, compress it into a small set of keypoints with
> set abstraction, then let a grid of points inside each proposal gather features from those keypoints.

Voxel Set Abstraction at backbone level $k$, for keypoint $p_i$:

$$
S_i^{(l_k)} = \Big\{ \big[ f_j^{(l_k)} ;\, v_j^{(l_k)} - p_i \big] \;:\; \lVert v_j^{(l_k)} - p_i \rVert < r_k \Big\},
\qquad
f_i^{(pv_k)} = \max\Big\{ G\big(\mathcal{M}(S_i^{(l_k)})\big) \Big\}
$$

- $f_j^{(l_k)}$, $v_j^{(l_k)}$: feature and 3D centre of non-empty voxel $j$ at level $k$; $r_k$: search radius.
- $\mathcal{M}$: randomly keep at most $T_k$ voxels; $G$: a shared MLP; $\max$: channel-wise max pool — the PointNet
  recipe, now applied to **voxels** instead of raw points.
- Final keypoint feature: $f_i^{(p)} = [f_i^{(pv_1)}, \dots, f_i^{(pv_4)}, f_i^{(raw)}, f_i^{(bev)}]$.

### The pipeline, step by step

1. **Voxelize** the scan; a non-empty voxel's feature is the mean of its points (coordinates + reflectance).
2. **3D sparse CNN**: $3 \times 3 \times 3$ sparse convolutions, four levels at $1\times, 2\times, 4\times, 8\times$ downsampling.
3. **RPN**: stack the $8\times$ volume along Z into a BEV map; anchor-based proposals (two anchors per BEV
   cell per class, at 0° and 90°, class-average size), as in SECOND.
4. **Keypoints**: FPS picks $n$ keypoints from the raw points.
5. **VSA**: each keypoint aggregates voxel features from all four levels, raw points, and the BEV map.
6. **Predicted Keypoint Weighting (PKW)**: re-weight each keypoint feature by its predicted foreground score.
7. **RoI-grid pooling**: $6 \times 6 \times 6$ grid points per proposal gather keypoint features.
8. **Refinement head**: 2-layer MLP, then a confidence branch (IoU target) and a box-residual branch.

> **Builds on.** The 3D sparse voxel CNN and anchor-based RPN of SECOND
> ([walkthrough 04](/walkthroughs/object-detection/second/)).

### Tensor shapes (KITTI)

| Stage | Operation → purpose | Shape |
|---|---|---|
| Input range | X $[0, 70.4]$ m, Y $[-40, 40]$ m, Z $[-3, 1]$ m → *the region that is voxelized* | raw points |
| Voxel grid | voxel size $(0.05, 0.05, 0.1)$ m → *fine voxels for the sparse CNN* | $1408 \times 1600 \times 40$ (range ÷ voxel size) |
| Sparse CNN levels 1–4 | 3D sparse convs, $1\times, 2\times, 4\times, 8\times$ downsampled → *efficient multi-scale 3D features* | 16, 32, 64, 64 channels |
| Proposals | BEV anchor RPN, NMS IoU 0.7 → *high-recall boxes from the voxel branch* | top 100 at test |
| Keypoints | FPS on raw points → *a few thousand well-spread points that summarise the scene* | $n = 2048$ (Waymo: 4096) |
| VSA radii per level | two radii each → *every keypoint gathers multi-scale voxel features around it* | (0.4, 0.8), (0.8, 1.2), (1.2, 2.4), (2.4, 4.8) m; raw points (0.4, 0.8) m |
| Keypoint weighting | 3-layer MLP + sigmoid, feature × score → *favour keypoints on objects over background* | $n \times C$ (same as VSA output) |
| RoI-grid pooling | per proposal, each grid point pools the nearby keypoints → *box features with exact positions inside the box* | $6 \times 6 \times 6 = 216$ grid points, radii (0.8, 1.6) m |
| RoI feature | flatten grid features, 2-layer MLP → *one vector per proposal* | 256-d per proposal |
| Heads | IoU-guided confidence + box residual → *a score that reflects box quality, and a refined box* | one score and one box per proposal |

- Waymo: range $[-75.2, 75.2]$ m in X and Y, $[-2, 4]$ m in Z, voxel size $(0.1, 0.1, 0.15)$ m.

### Voxel Set Abstraction: a few thousand keypoints summarise the scene

- The "neighbours" of a keypoint are now **voxels with learned multi-scale features**, not raw points.
- Each level has two radii, so every keypoint sees four levels × two scales of context.
> **Builds on.** Farthest point sampling and set abstraction from PointNet++
> ([walkthrough 01](/walkthroughs/object-detection/pointnet/)) — applied here to voxels instead of raw points.

- **Extended VSA** adds two more sources:
  - $f^{(raw)}$: set abstraction on raw points — recovers detail lost in voxelization;
  - $f^{(bev)}$: bilinear interpolation on the $8\times$ BEV map — a larger receptive field along Z.
- Every source helps a little; the deep levels matter most. Raw points alone give 81.98 moderate AP;
  all sources together give 84.83 (Table 8, KITTI val).

### Predicted Keypoint Weighting

- FPS spreads keypoints evenly, so many describe background.
- A three-layer MLP with sigmoid predicts a foreground score per keypoint:
  $\tilde f_i^{(p)} = \mathcal{A}(f_i^{(p)}) \cdot f_i^{(p)}$.
- Labels come for free, as in PointRCNN: a keypoint inside a ground-truth box is foreground. Trained with focal loss.

> **Builds on.** PointRCNN's free segmentation labels from boxes
> ([walkthrough 06](/walkthroughs/object-detection/pointrcnn/)).
- Removing PKW: 84.83 → 82.95 moderate AP (Table 9).

### RoI-grid pooling: points that reach beyond the box

- Sample $6 \times 6 \times 6$ grid points $g_i$ in each proposal; each gathers keypoints within radius $\tilde r$:
  $\tilde f_i^{(g)} = \max\{ G(\mathcal{M}(\tilde\Psi)) \}$, with $\tilde\Psi$ the set of $[\tilde f_j^{(p)}; p_j - g_i]$.
- Two radii per grid point; the balls can extend **outside the box** to capture context.
- Compared with PointRCNN's pooling (points inside the box) and Part-A² RoI-aware pooling (many empty voxels),
  this reads only informative keypoints.
- Replacing it with RoI-aware pooling: 84.83 → 82.97 moderate AP (Table 9).

### Heads and losses

- Confidence target from the 3D IoU with the ground truth: $y_k = \min(1, \max(0, 2\,\mathrm{IoU}_k - 0.5))$,
  trained with binary cross-entropy. A plain classification target gives 82.50 instead of 84.83 (Table 9).
- Box residuals as in SECOND, smooth L1.
- Total loss $L = L_{rpn} + L_{seg} + L_{rcnn}$, equal weights; trained end to end
  (PointRCNN trained its two stages separately).
- Training: 128 proposals per scene, 1:1 positive/negative, positive if 3D IoU ≥ 0.55; final NMS threshold 0.01.

### Pros and Cons

- **Pros**
  - Voxel CNN for high-recall proposals, set abstraction for flexible, multi-scale RoI features.
  - Keypoints compress the scene into a small, fixed-size set; RoI-grid points can look beyond the box.
  - Trained end to end; large gains far away on Waymo (+9.19 at 30–50 m).
- **Cons**
  - Slow: Voxel R-CNN later measures 8.9 FPS, with Voxel Set Abstraction taking about half the run time.
  - Still anchor-based proposals, with per-class anchor sizes and fixed headings.
  - Two parallel scene representations (voxels and keypoints) make the pipeline complex.

### Future Work

- Drop anchors in favour of a simpler output representation.
- Find out whether refinement really needs keypoints and raw points, or whether voxel features suffice.
